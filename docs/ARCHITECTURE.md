# Native stock-Mali wrapper

PixelBC is an Android HAL wrapper for NFS Mobile 0.4.0 and a separate Unleashed 0.6.0 integration candidate. It keeps the stock ARM driver, compiler, dispatchable handles, queues, Android native-buffer entrypoints and presentation synchronization. Version0.1.2 adds BC7 and faithful compressed copies/readback to BC1–5 GPU decoding into RGBA8 backing images. The user reports0.1.1 Pixel probe347/0 twice with normal exit and actual NFS race decoding. Version0.1.2 device acceptance and performance remain pending.

## Why a focused wrapper

The pinned [Leegao wrapper](https://github.com/leegao/bionic-vulkan-wrapper/tree/c8baafbd4f4835ca103acb55ec3ac13642b6b7e3/src/vulkan/wrapper) contains useful shader and interception precedents, but its `wrapper_instance.c` opens `/system/lib64/libvulkan.so`, which is an unsafe backend choice inside a custom-driver loader. It has no Android HMI export. Its physical-device code adds unsupported linear/storage/buffer/blit flags, and its device/graphicsenv paths include feature overrides, Winlator paths, SPIR-V rewriting and Mesa WSI. Porting that complete stack would preserve more unrelated behavior and create another presentation boundary. This implementation uses newly written runtime code and a smaller dependency boundary; only its independent CPU test reference is copied from pinned upstream.

The strongest alternative is adapting the Mesa wrapper with native HAL plumbing and auditing every intercepted contract. Reopen that choice if a broader consumer requires BC6, transfer-only queues, secondary-buffer uploads, or shader-object/descriptor-buffer state. This candidate targets the inspected NFS and Unleashed upload paths and makes unsupported paths fail explicitly.

## Loader and WSI

The library exports a 248-byte LP64 `HMI` object and Vulkan GPA entrypoints. Its HAL opens `vk0`, then ordinary `dlopen("/vendor/lib64/hw/vulkan.mali.so", RTLD_NOW|RTLD_LOCAL)` obtains the real vendor HAL. Handle-specific HMI lookup checks identity, tags, ABI versions, callbacks and self-recursion, sets the backend module's `dso`, and opens its `vk0`. From0.1.1 the owned stock HAL and vendor DSO reference remain alive for process lifetime. Android builds mark the wrapper ELF `DF_1_NODELETE`, retaining the mapping/static state when an application releases its loader reference with `dlclose`. Vulkan objects are still destroyed normally; the probe closes its own allocated wrapper HAL, calls `dlclose`, then returns naturally. A process restart is required to replace/reinitialize a loaded driver version. Retained mappings/HAL state consume memory until process exit and are a deliberate containment policy, not proof of the original crash cause. There is no system-loader backend, Winlator server, private graphicsenv manipulation, driver blob redistribution or dependency on libadrenotools inside this library.

[Adrenotools 8fae8ce](https://github.com/bylaws/libadrenotools/blob/8fae8ce254dfc1344527e05301e43f37dea2df80/src/hook/hook_impl.cpp#L46) loads custom drivers in a shared child of the supplied driver namespace. Its [main hook](https://github.com/bylaws/libadrenotools/blob/8fae8ce254dfc1344527e05301e43f37dea2df80/src/hook/main_hook.c#L3) intercepts `android_dlopen_ext` and the SP-HAL helper in a separate loader namespace, rather than ordinary `dlopen` in the driver. [Bionic](https://github.com/aosp-mirror/platform_bionic/blob/731631f300090436d7f5df80d50b6275c8c60a93/linker/linker.cpp#L2505) copies parent search paths and namespace links. This supports the chosen route; it does not prove resolution on this phone. Android17 can use an APEX driver namespace, and the actual Pixel vendor dependencies remain device checks.

The pinned Android17 [built-in Vulkan loader](https://github.com/GrapheneOS/platform_frameworks_native/blob/1c83ac6ae533c74ecb0486369c0d2f9e79783b3d/vulkan/libvulkan/driver.cpp) retains its ordinary HAL/DSO without a destructor. Its explicit unload path is for updated-driver transition. The Android HAL ABI permits close/unload; this candidate adopts the ordinary process-lifetime policy because cached loader callbacks require live code and the0.1.0 crash had an unmapped PC. No tombstone yet establishes whether that PC belonged to wrapper, vendor driver or another library. Bionic `NODELETE` suppresses `dlclose` unload/finalizers, but ordinary exit still runs C++ destructors; omitting explicit vendor close/dlclose from `Backend` also avoids calling into vendor state after its later-registered exit destructors.

All unhandled GPA/GDPA functions, non-BC images and native-buffer structures go directly to the backend, including `vkAcquireImageANDROID`, `vkQueueSignalReleaseImageANDROID`, gralloc usage variants and external synchronization. No fence wait, queue submission or Android release operation is bypassed. The stock handles retain the Android loader's expected dispatch-header layout.

## Truthful formats and limits

Twelve BC1–5 variants and BC7 UNORM/SRGB map to RGBA8 UNORM, SRGB or SNORM. BC4 has R/0/0/1 and BC5 R/G/0/1; signed variants keep signed channels, with -128 endpoints clamped to -127. SRGB bytes undergo no gamma conversion during upload; SRGB views perform the usual sampling conversion. BC1 RGB's transparent selector stays opaque black, while BC1 RGBA keeps transparent black. BC2/3 always use four-color interpolation. BC7 implements all eight modes, partition/anchor tables, endpoint precision/p-bits, rotation and dual index selection. Its separate probe checks exact decoder bytes against pinned bcdec plus literal fixtures and real wrapper sampling/readback.

Optimal-tiling queries expose sampled-image, linear-filter and transfer-source/destination bits when the backing format supports them. Linear tiling and buffer feature planes are zero. Only optimal 2D, one-sample sampled/transfer images, mip chains and array/cube layers are admitted. External image chains, storage/attachment usages and sparse/protected images are rejected. Mutable views allow the exact original format or its same-family UNORM/SRGB twin; differing BC families or signedness cannot reinterpret already decoded bytes. The maintenance4 image-memory query applies the identical target/view-list mapping. BC6 query planes are zero and creation explicitly returns unsupported.

`textureCompressionBC` is false in both feature APIs and cannot be enabled: it guarantees all BC1–7. [Khronos](https://github.com/KhronosGroup/Vulkan-Docs/blob/e4e53e4b31e13eeaee1ad99fb940aa72b2ec1b14/chapters/features.adoc#L440) expressly permits individual format support without that bit. API reporting is capped at Vulkan1.3. Features/extensions that change compute binding semantics outside the implementation (maintenance5/6, push descriptors, shader objects, descriptor buffers and generated commands), host-image-copy and protected-memory feature advertisement are disabled.

This is a scoped candidate, not a Vulkan conformance implementation. Supported BC image copies preserve both decoded bytes and original blocks within the same decode family. Mixed BC/uncompressed, differing-family copies and secondary BC commands fail recording/submission explicitly. All requested device queues must support compute and be unprotected. Ordinary non-BC image-copy paths remain native. These deliberate copy limitations are narrower than full Vulkan compressed-format conformance.

[NFS's pinned native renderer](https://github.com/codepdbh/nfsmw-android/blob/6df1501974d0db84893f5a3ca465b616414f6961/app/src/nfsmw_nativo_dibujos.cpp#L2195) checks sampled + linear-filter + transfer-destination flags independently for BC1_RGBA, BC2, BC3, BC4 and BC5 UNORM. It uses optimal 2D/cube mip images and [buffer uploads in GENERAL](https://github.com/codepdbh/nfsmw-android/blob/6df1501974d0db84893f5a3ca465b616414f6961/app/src/nfsmw_nativo_dibujos.cpp#L9782). Its device setup does not enable the all-family BC bit. Thus per-format support can select NFS's BC upload path without pretending to implement BC6/7.

## Decode ordering, state and ownership

Each region records source-buffer copy → transfer-to-compute barrier → compute decode into an owned RGBA buffer → compute-to-transfer barrier → standard buffer-to-image copy. The original input buffer needs only its existing transfer-source usage, with no storage-offset alignment assumptions. The final image write remains a transfer write in the caller's requested GENERAL or TRANSFER_DST layout, so the caller's normal transfer synchronization applies. There are no inserted image-layout changes or asynchronous side submissions.

Input addressing includes padded block rows, layer strides, nonzero offsets, partial edge blocks and tiny mips. Checked multiplication/addition rejects overflowing sizes before allocation. Storage-range and workgroup limits are checked before dispatch.

Images with TRANSFER_SRC own a separate GPU buffer retaining tightly packed original blocks for each mip/layer. Uploads update that store; readback copies exact compressed bytes with caller pitch/offset, leaving padding untouched. Image copies preserve original blocks and native RGBA bytes. Upload-only images, including the inspected NFS path, incur no store allocation or extra compressed copy. Commands retain stores until reset/free, and mirrored pipeline/event image dependencies preserve stage/access/family scopes over corresponding buffer ranges. Native semaphores, submission and fences remain unchanged. [BC_TRANSFER_INTERNAL.md](BC_TRANSFER_INTERNAL.md) documents ownership, unsupported operations and exact Unleashed source call sites.

Injected compute work restores caller pipeline, descriptor-bind history and complete stage-specific push history. Compatible wrapper-owned pipeline layouts are cloned at caller layout creation and retained for recorded replay; caller layout destruction is immediate. Upload buffers, memory and descriptor pools belong to the command recording, survive submission/replay, and are released on successful command-buffer/pool reset, implicit rerecord, free, pool destruction or device destruction. The application remains responsible for normal pending-command synchronization. Errors are retained and reported by EndCommandBuffer and legacy/Submit2 submission; no failed decode is reported as a successful upload.

The simple per-region staging/pool allocations and retained binding histories are correctness-first costs. They may reduce or eliminate any speed advantage on Mali. Resource pooling and tuning require measured device evidence and must preserve these lifetime/state boundaries.

## Decode precision

There is no ETC2 transcoding or other texture recompression. The output is conventional decoded RGBA8 (or signed RGBA8). This is not a promise of bit-identical interpolation across every Vulkan/CPU implementation: reference comparisons allow one 8-bit LSB, and the executed synthetic suite observed a maximum of one. Literal endpoint, transparency and signed anchors, and the full cube mip chain use exact expected bytes. Visual fidelity and filtering on the real Mali driver still require local tests.

PixelBC0.1.1 left the runtime GLSL decoder unchanged;0.1.2 adds BC7 while preserving the BC1–5 routines. Signed integer shifts generate arithmetic sign extension. The reproduced failure was in the CPU reference's plain-char endpoint interpretation. The probe directly executes the same decoder SPIR-V into an SSBO before independently sampling literal RGBA8_SNORM bytes; each path reports separately from the full BC upload comparisons. SNORM encoded -128 and -127 both reconstruct to canonical -127, and unsigned/signed alpha conventions remain unchanged.
